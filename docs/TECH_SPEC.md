Исторические контракты расширений: [EXPANSION_V02.md](EXPANSION_V02.md), [PLANS_V03.md](PLANS_V03.md). Первоначальные промпты v0.1 сохранены в `prompts/` как история этапов.

## Инструменты и идентификаторы

| Компонент | Закреплённая версия |
| --- | --- |
| Minecraft Java Edition | 26.3 |
| Fabric Loader | 0.20.1 |
| Fabric API | 0.165.0+26.3 |
| Fabric Loom | 1.19.3, plugin `net.fabricmc.fabric-loom` |
| Gradle Wrapper | 9.8.2; SHA-256 в wrapper properties |
| Java toolchain | 25 |
| Мод | BlockBill 0.4.1, modid `blockbill`, package `dev.blockbill` |

Официальная база: [Fabric example mod, ветка 26.3](https://github.com/FabricMC/fabric-example-mod/tree/26.3). Имена Minecraft необфусцированные; старые примеры Yarn не используются как контракт. Проверенные сигнатуры: [API_RESEARCH.md](API_RESEARCH.md), [API_V02.md](API_V02.md).

Основной entrypoint — `dev.blockbill.BlockBillMod`; клиентский — `dev.blockbill.client.BlockBillClient`. Серверный код не зависит от клиентских классов. Два общих Mixin закрывают отсутствующие Fabric hooks спринта и перехода порталом; сигнатуры и ограничения описаны в PROGRESSION_API_V04.md. Интеграция боковой панели инвентаря находится в клиентском source set; на dedicated server клиентские классы не загружаются. Два client-only accessor Mixin (`ContainerScreenLayoutAccessor`, `RecipeBookScreenAccessor`) дают доступ к закрытой геометрии окна, книге рецептов и истории последнего клика. Fabric не предоставляет эти поля: нужно сдвинуть обычные слоты рядом с панелью и разорвать double-click при клике по управлению модом. Ванильный рендер не отменяется; панель рисуется через `ScreenEvents.afterForeground`, ввод — через Fabric screen events. При закрытии восстанавливаются положение и книга рецептов. Совместимость с другими модами, также меняющими эти поля, отдельно не проверена.

## Структура

Один Gradle-проект, отдельные source sets:

- `src/main/java/dev/blockbill/domain/`: `PlayerAccount`, `ServiceType`, `SubscriptionBundle`, `SubscriptionEngine`, `ExchangeOffer`, `ExchangeService`, `SprintTracker`, `TransactionResult`.
- `src/main/java/dev/blockbill/infrastructure/Accounts.java`: мировое SavedData и codec.
- `src/main/java/dev/blockbill/fabric/`: команды, события, адаптер инвентаря, ограничения взаимодействий.
- `src/client/java/dev/blockbill/client/`: InventoryTabs, HubClient, боковая панель BlockBillHubScreen и встроенная справка.
- `src/main/java/dev/blockbill/market/`: ItemPriceCatalog и атомарные MarketSales.
- `src/main/java/dev/blockbill/network/`: HubRequest, HubState, AccessState и HubServer.
- `src/main/java/dev/blockbill/mixin/`: EntityPortalMixin и LivingEntitySprintMixin.
- `src/main/resources/`: `fabric.mod.json`, `blockbill.mixins.json`, RU/EN локализации и 1657 цен в `assets/blockbill/item_prices.json`.
- `src/test/`: чистые доменные тесты; `src/gametest/` и `src/clientGametest/`: игровые проверки в тестовом моде, не в итоговом JAR.

## Домен и время

`PlayerAccount` хранит UUID, целые credits и creditRemainder (0…99), activePlayTicks, trialEndTick, сроки по `ServiceType`, флаги автопродления, adUntilTick и adReadyAtTick. `Snapshot` — неизменяемое представление для сохранения. Домен не зависит от Minecraft; изменение счетов выполняется только в логическом серверном потоке.

- Trial: 6000 активных survival-тиков. `tick(boolean survival)` увеличивает часы только в survival, без переполнения.
- `hasAccess(account, service)`: activeTicks меньше trialEnd, оплаченного срока или adUntilTick. Равенство означает истечение.
- `purchase(account, service)`: цена конкретной услуги, 12000 тиков.
- `purchaseBundle(account, bundle)`: цена, набор и durationTicks взяты из `SubscriptionBundle`. Обычные пакеты — 12000, Plus — 18000, Pro — 36000, Business — 72000.
- `purchaseAll(account)` — All Access: **120 кредитов, десять услуг по 12000 тиков**. Прежний состав трёх услуг за 40 соответствует `BASIC`.
- Каждый новый срок — `Math.addExact(max(activeTicks, trialEnd, currentExpiry), durationTicks)`.
- Покупка сначала рассчитывает все будущие сроки, затем списывает стоимость и применяет результат. Overflow последней услуги не допускает частичных изменений предыдущих.
- Тарифы раскрываются в отдельные сроки услуг. Глобального ранга аккаунта или командного счёта нет; покупка Plus после Pro/Business не сокращает доступ.
- `renewDue(account)` вызывается только для online survival: продлевает включённые истёкшие услуги индивидуально на 12000 тиков. Неудача отключает соответствующий флаг. Порядок — enum `ServiceType`; пакеты не автопродлеваются. Покупка тарифа не меняет флаги.

## Команды и транзакции

Команды регистрируются через `CommandRegistrationCallback`. `status`, покупки, обмен, настройки автопродления и debug требуют `ServerPlayer`. `help`, `prices`, `services`, `plans` доступны также из консоли.

`exchange`: проверить survival и число наборов → подсчитать подходящие предметы всех личных слотов → проверить будущий баланс без overflow → списать точное количество → начислить кредиты → отметить SavedData dirty → отправить результат. Внешние контейнеры не участвуют. `logs` принимает предметы тега LOGS только из namespace `minecraft`; остальные предложения сопоставляют точный ванильный Item. Диапазон bundles: 1…1 000 000.

`buy`: проверить survival → получить счёт → проверить баланс и все будущие сроки → единожды списать цену и применить сроки → dirty → одна квитанция с динамической длительностью. `all` изменяет десять сроков, `basic` — три. Ни один отказ не меняет баланс или срок.

`debug credits` устанавливает баланс собственного игрока и защищён `Permissions.COMMANDS_GAMEMASTER`. Отрицательные суммы не принимаются. Обычные клиенты не могут передавать серверу готовое состояние счёта.

## Fabric и поведение игры

- `ServerTickEvents.END_SERVER_TICK`: один проход по онлайн-игрокам; время, автопродление, остановка запрещённого спринта и очередь уведомлений. Сканирования чанков нет.
- `EntitySleepEvents.ALLOW_SLEEPING`: проверка Sleep+ на сервере. Возвращается `BedSleepingProblem` с локализованной причиной. Ванильная установка respawn обычной кроватью сохраняется; Straw Bed следует собственным правилам Minecraft.
- Mine+: `AttackBlockCallback` отклоняет начало; `PlayerBlockBreakEvents.BEFORE` повторно проверяет доступ перед разрушением. Запрещены BlockTags.ORES, ancient debris на любой высоте и любой блок ниже Y40.
- Sprint+: `LivingEntitySprintMixin` фильтрует `LivingEntity.setSprinting`, серверный tick также сбрасывает запрещённый спринт. Client AccessState управляет предсказанием своего игрока, сервер проверяет независимо. Новых Mining Fatigue/Slowness нет; чужие эффекты сохраняются.
- Travel+: `EntityPortalMixin` проверяет `Entity.teleportToPortalDestination` до переноса в Nether/End, включая пассажиров. Возврат в Overworld свободен. Поиск/создание выхода портала могло выполниться раньше hook; после отказа действует ванильный cooldown. Прямой административный teleport не ограничен.
- `UseBlockCallback`: Enchant+, Anvil+, Smith+, Storage+ до открытия окна. Вторичное использование с занятыми руками пропускается к ванильной установке/использованию предмета.
- `UseEntityCallback`: Trade+ для взрослого свободного живого жителя или странствующего торговца, с сохранением посторонних взаимодействий.
- `UseItemCallback`: Fish+ перед новым забросом; существующая удочка разрешена к сматыванию после истечения.
- На клиенте ограничиваемое взаимодействие возвращает Fabric SUCCESS для отправки пакета; сервер независимо разрешает или отклоняет ванильное действие. Отказы не создают меню и не расходуют предметы.
- `ServerPlayerEvents.AFTER_RESPAWN` и disconnect очищают временный session state. Персистентный счёт находится в мире и сохраняется при смерти.

## Сохранение и совместимость

`Accounts` — один SavedData в Overworld с `Identifier blockbill:accounts`, ключи игроков — UUID. Dirty отмечается после транзакций и периодически, а также при отключении и остановке мира; это пометка для штатного сохранения, не синхронная запись каждый тик.

Codec сохраняет семь обязательных полей v0.1: uuid, credits, activeTicks, trialEnd, mineUntil, sleepUntil, sprintUntil. v0.2 добавляет необязательные `extraPaidUntil` и `autoRenew` с пустыми значениями по умолчанию. Неизвестные будущие ID сохраняются без активации и списаний. v0.3 не вводит отдельное поле тарифа: его результат уже представлен сроками услуг. v0.4 добавляет необязательные `creditRemainder` (0…99), `adUntil`, `adReadyAt` (неотрицательные), по умолчанию 0. Travel — новый ID extraPaidUntil, старые enum ordinals не сдвигаются. Повторный trial и бесплатный Travel не выдаются.

Контракт v0.3.1: повреждённый NBT, невалидные суммы/сроки и повторные UUID не должны молча заменяться пустыми счетами и перезаписывать прежний файл. Загрузка должна сообщить ошибку до изменения состояния; первичный новый мир без файла остаётся допустимым. Результаты проверки этой защиты записываются отдельно в `PROGRESS.md`.

## Справка и локализация

`ScreenEvents.AFTER_INIT` добавляет вкладку BlockBill к InventoryScreen и CreativeModeInventoryScreen через `Screens.getWidgets`. InventoryTabs сохраняет один экземпляр ванильного экрана и раскрывает боковую панель Обзор/Тарифы/Продажа/Реклама/Правила. Ванильные слоты, крафт и управление предметами остаются видимыми рядом с панелью. Закрытие панели возвращает обычный вид инвентаря; предметы и серверное inventoryMenu не заменяются.

Клиентская интеграция размещает панель и ванильный инвентарь рядом, сохраняя их отдельные области ввода. Инициализация, изменение размера, tick и удаление экрана обрабатываются через ScreenEvents. События мыши и клавиатуры направляют ввод панели в её widgets. Вне режима продажи клики по ванильным слотам сохраняют обычное поведение. «Купить кредиты» включает SELL: клик по реальному личному слоту выбирает его индекс для серверной оценки, не поднимая стек на курсор. Продажа выполняется только после подтверждения в панели. Внешние/крафтовые/творческие каталожные слоты не становятся источником продажи. Закрытие панели завершает серверный сеанс Hub и отменяет незавершённую рекламу. Все 15 разделов справки RU/EN отображаются постранично внутри панели «Правила», без перехода на отдельный Screen. Панель, инвентарь и чтение правил не ставят мир на паузу; активные тики подписок продолжаются.

`HubRequest(action,value,slot,amount,revision)` содержит только намерение. Серверные PayloadTypeRegistry/ServerPlayNetworking обрабатывают его в потоке сервера. HubState передаёт JSON с балансом, доступом, сроками, каталогом и копией инвентаря. Полная схема — V04_CONTRACT.md. Клиент не передаёт цену, баланс, UUID или срок как источник истины.

HubServer хранит ограниченный сеанс по UUID. OPEN/REFRESH создают свежую цену с revision и копиями стеков. BUY/AUTO/SELL/AD_START/AD_CLAIM требуют актуальную revision и потребляют её, включая неудачный запрос; повтор не повторяет транзакцию. SELL проверяет ItemStack.matches с количеством и компонентами, доступный личный слот, survival, собственный inventoryMenu и пустой курсор. Будущий баланс проверяется до удаления. Любое несоответствие отклоняет операцию целиком. Итог синхронизирует меню и Hub. Legacy exchange использует MarketSales и те же цены.

Сеанс требует REFRESH раз в 20 клиентских тиков, истекает после 100 серверных тиков без обращения, закрывается CLOSE/disconnect. Ограничение частоты — 30 запросов на 20 серверных тиков. Каталог отдаётся по 45 предметов, порядок стабильный, фильтр по registry ID. AccessState передаёт изменившуюся маску доступа раз в 20 серверных тиков.

AD_START запоминает активное время; AD_CLAIM после 100 survival-тиков открытого просмотра задаёт adUntil=now+600 и adReadyAt=now+1800. AD_CANCEL, уход с вкладки и CLOSE отменяют просмотр. Reward/cooldown сохраняются, незаконченный просмотр — нет. Повторная награда до cooldown и переполнение отклоняются. Paid deadlines/flags не изменяются, обычный отсчёт продолжается. Автопродление ждёт окончания рекламного доступа.

Все пользовательские сообщения — translatable Components RU/EN. Цена конкретного стека уменьшается от износа; зачарования/имя не добавляют стоимость. Непустые ContainerComponent, BEES, CONTAINER_LOOT и поддерживаемые block entity Items/LootTable защищены от продажи. Registry validation требует явную цену каждого vanilla Item кроме AIR; modded fallback — 1 цент с предупреждением.

Фоновые сообщения ограничены одним на 600 активных тиков. Предупреждения формируются за 1200 тиков до истечения и объединяются по типу; нерелевантные удаляются из очереди. Сводные автосписания используют тот же предел. Явный отказ взаимодействия показывает название, цену и путь к покупке в инвентаре, с отдельным пределом 20 тиков на игрока.

## Валидация и границы

Обязательные группы: точные границы trial/expiry; десять услуг и семь пакетов/тарифов; раннее и смешанное продление; атомарность отказов и overflow; индивидуальное автопродление и порядок; разные UUID; полный каталог, рецептные ограничения, дробные суммы, stale/replay quotes, защищённые вложения и смешанные stacks; реклама 100/600/1800 тиков и отмена; сохранения v0.1/v0.2/v0.3, повторный запуск и повреждения; реальные server/client взаимодействия; RU/EN справка и изменение размера; боковая панель в том же экземпляре экрана, видимость и обычное перемещение предметов в ванильных слотах, выбор реального слота без перемещения только в режиме продажи.

Команды: `./gradlew clean test build`, `./gradlew runGameTest`, `./gradlew runClientGameTest`. Тестовые сценарии и фактические результаты — в `PROGRESS.md`. Green build и автоматические GameTests не равны человеческому плейтесту баланса или завершённому прохождению.

Не входят: новые предметы/мобы/биомы, реальные платежи, внешняя экономика, сеть авторизации, телеметрия, общая БД, Forge/NeoForge и Bedrock.
